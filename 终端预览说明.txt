四、完整成功示例（按源码推导的预期，非实测）
--------------------------------------------

命令（在已准备好 sample.sqlite、且含 query.sql 的目录执行）：

    python report.py --db sample.sqlite --sql-file query.sql \
        --param who=小明 --null-text 未填写 --preview 1

    import report
    sql_text = report.read_sql_file("query.sql")
    count = report.preview_csv(
        "sample.sqlite", sql_text, 1,
        params={"who": "小明"}, null_text="未填写",

六、N 只限制展示行数；CSV 规则；不建文件、不改源库与查询文件
------------------------------------------------------------

1. N 只在输出端切片：shown = rows[:limit]（report.py:526），不会向 SQL
   文本注入任何 LIMIT；查询自身的筛选、排序与 LIMIT 语义原样保留。
   - N 大于结果行数时全部显示：JOIN_SQL 共 2 行，limit=10 返回 2
     （test_function_limit_above_result_count_returns_two，
     test_preview.py:157-166）。
   - 查询自带 ORDER BY p.id DESC LIMIT 1 时只显示小红一行，排序与 LIMIT
     由 SQL 决定而非 N：test_function_descending_with_limit_one_shows_
     xiaohong（test_preview.py:179-191）。
2. 特别澄清：N 不限制取数数量。_fetch_rows 总是 cursor.fetchall() 取回
   全部结果（report.py:435），切片发生在取数与连接关闭之后
   （report.py:526）。因此不应理解为“预览只从数据库读取 N 行”——第七节
   的整数溢出就是“N=1 仍要对全部结果求值”的直接反证。
3. CSV 规则与文件导出相同：csv.writer 默认 excel 方言（report.py:524，
   与 export_csv 的 report.py:481 同一写法）。小红备注
   '中文,含"引号"' 经 csv.reader 完整还原为一个字段：函数用例
   test_function_limit_above_result_count_returns_two（157-166）；命令行
   用例 test_cli_default_format_matches_explicit_csv
   （test_preview.py:242-257）同时断言默认格式与显式 --format csv 的
   标准输出逐字节一致（253）。NULL 仅按 null_text 替换（528），非空值、
   列名、列顺序与行顺序不受影响。
4. 预览不创建报告或临时文件，源库与查询文件保持不变。这一点有测试夹具
   层面的统一断言：tearDown 中重新以只读方式打开源库，核对两表结构与
   全部数据与准备基线一致（test_preview.py:68；快照逻辑 100-117），
   核对临时目录文件清单与基线一致（70；清单逻辑 119-125），并逐字节
   核对查询文件未变（72-73）；命令行参数用例还额外复核了查询文件字节
   （test_preview.py:275-277）。源码侧依据：只读 URI 开库
   （report.py:372-378）、查询文件只以二进制读方式打开
   （report.py:355-356）、预览路径全程无 open(..., "w"/"x") 调用
   （524 行的 csv.writer 只包装 sys.stdout）。


七、为什么预览一行也可能整体失败：整数溢出与“先取完再输出”
-----------------------------------------------------------

使用如下查询（test_preview.py:42 的常量 OVERFLOW_SQL）：

    SELECT 1 AS 数值 UNION ALL SELECT abs(-9223372036854775808)

第一项 SELECT 1 完全合法；第二项 abs(-9223372036854775808) 的数学结果
是 2^63，超出 64 位有符号整数范围，SQLite 在对该行求值时抛出
“integer overflow”。

按当前源码的失败时序：

1. limit=1 通过正整数校验（report.py:507-508），SQL 通过单条 SELECT
   校验（514），无参数（bind_params 返回 None，report.py:336-337），
   只读开库成功（517）。
2. cursor.execute(statement) 成功（report.py:426）——语句开始执行阶段
   尚不能暴露第二行的求值错误；列名“数值”由 description 取得
   （report.py:433）。
3. cursor.fetchall()（report.py:435）在取回第二项结果时触发 sqlite3.Error，
   被 436-437 捕获并统一包装为
   ValueError("SQL 执行失败：…integer overflow…")（包装格式见
   report.py:437；两个判定子串的常量见 test_preview.py:43-44）。
4. 连接在 finally 中照常关闭（report.py:520-521）。csv.writer 在
   fetchall 成功之后才创建（report.py:523-524），因此此刻标准输出尚未
   写入任何内容，连表头都不会出现——不存在“部分预览”。
5. 函数入口：preview_csv 抛 ValueError。已有断言
   test_function_overflow_raises_valueerror_empty_stdout
   （test_preview.py:217-227）：assertRaises(ValueError)、异常消息同时
   包含“SQL 执行失败”和“integer overflow”、重定向到缓冲区的标准输出
   为 ""（227）。
6. 命令行：

       python report.py --db sample.sqlite \
           --sql "SELECT 1 AS 数值 UNION ALL SELECT abs(-9223372036854775808)" \
           --preview 1

   ValueError 由 main 的 except 捕获交 die（report.py:752-753、67-70）：
   退出码 1（70）；标准输出为空（758 不可达）；标准错误包含“SQL 执行
   失败”与“integer overflow”（“错误: ”前缀来自 report.py:69，完整
   逐字文本按源码推导）。已有断言
   test_cli_overflow_exit_one_stderr_reason_empty_stdout
   （test_preview.py:333-341）：returncode == 1、stderr 含两个子串、
   stdout == ""。

一般结论：当前流程是“先取完全部结果，再开始输出”，任一后续行在
fetchall 期间求值失败，都会拒绝整个结果，即使第一行本身毫无问题、即使
N=1。


八、拒绝情形汇总（函数 ValueError；命令行退出 1、标准输出为空）
----------------------------------------------------------------

A. 函数 preview_csv 的非法行数（report.py:507-508）

   条件 not isinstance(limit, int)、isinstance(limit, bool) 或
   limit < 1 任一成立即抛 ValueError("preview 行数必须是正整数，
   收到 %r")。零、负数、布尔值、非整数全覆盖：

       for bad_limit in (0, -1, True, "2", 2.5)

   已有断言 test_function_invalid_limit_raises_valueerror_empty_stdout
   （test_preview.py:205-213）：五种取值均 assertRaises(ValueError)，
   且重定向的标准输出为 ""（213）。此校验是 preview_csv 的第一步
   （507 在 513-519 之前），非法行数时不会校验参数、不会打开数据库。

B. 命令行缺少行数或行数非法（report.py:657-663、694-695、619-621）

   --preview 以 type=int 注册（report.py:659）：
   - 缺少值（--preview 后无参数）：argparse 报 “expected one argument”，
     经 _Parser.error 处理；
   - 非整数（如 abc、2.5）：argparse 的 int 转换失败，同一路径；
   - 零与负数（0、-2）：argparse 能转为 int，再由
     report.py:694-695 的 args.preview < 1 判定拒绝。
   三种情况都走 _Parser.error（619-621）：先 print_usage 向 stderr 写
   一行用法（620），再由 die 写“错误: 参数错误：…”（621、69），退出
   码 1（argparse 默认的退出码 2 被本类改写为 1，说明见 617-618）。
   已有断言 test_cli_invalid_preview_count_exit_one
   （test_preview.py:281-295），含“缺值/零/负数/非整数”四个 subTest：
   returncode == 1、stderr 含“错误”、stdout == ""。

C. 预览与导出类选项冲突（report.py:692-701）

   - 与 --output 同时提供：696-697 拒绝。已有断言
     test_cli_preview_with_output_rejected_no_file
     （test_preview.py:299-309）：退出 1、stderr 含“错误”、stdout 为空，
     并显式断言目标输出文件不存在（309）。
   - 与 --format html 同时提供：698-699 拒绝（706-709 另有
     “description 仅配 html”的通用判定）。已有断言
     test_cli_preview_with_format_html_rejected
     （test_preview.py:311-318）。
   - 与显式 --description 同时提供（即使传空字符串）：700-701 拒绝；
     命令行以 default=None 区分“未提供”与“提供空串”（report.py:685）。
