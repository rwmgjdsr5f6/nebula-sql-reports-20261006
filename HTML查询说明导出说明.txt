一、样例库与 query.sql
----------------------

本文样例沿用 test_report.py 中 people/notes 合成库（建表与插数见
test_report.py:59-81；说明专用测试类在 2634-2655 重复了同一准备
逻辑）：

    people(id INTEGER PRIMARY KEY, name TEXT NOT NULL)
    notes(person_id INTEGER PRIMARY KEY, note TEXT)

两条记录（test_report.py:70-78、2645-2652）：

    people: (1, '小明')、(2, '小红')
    notes:  (1, NULL)、(2, '中文,含"引号"')   -- NOTE_VALUE 常量见
                                               -- test_report.py:33

关联条件为 people p JOIN notes n ON p.id = n.person_id：小明的备注
是 SQL NULL（Python 端为 None），小红的备注是同时含中文、逗号与双
引号的文本。仓库本身不随附 sample.sqlite——.gitignore 第 6 行忽略
*.sqlite，下例假设你已按上述结构自行准备好该文件。

当前 query.sql 全文 4 行（query.sql:1-4），结尾分号后有一个换行：

    第 1 行  SELECT p.name AS 姓名, n.note AS 备注
    第 2 行  FROM people p JOIN notes n ON p.id = n.person_id
    第 3 行  WHERE p.name = :who
    第 4 行  ORDER BY p.id;

:who（query.sql:3）是唯一的命名参数占位符。首尾空白与单个结尾分号
属于允许形态（validate_single_select，report.py:191-226）。


二、公开入口与一条完整命令
--------------------------

两个公开入口：命令行 main（report.py:638-673）与库函数 export_html
（report.py:524-556）。函数入口接收 SQL 文本而非文件路径，故使用
query.sql 时需先经 read_sql_file（report.py:338-357）取文本——
main 在 report.py:644 正是这样做的。

完整命令（在含 sample.sqlite 与 query.sql 的目录执行；--format
显式选择 html，who=小明，空值标记“未填写”，查询说明“筛选小明”）：

    python report.py --db sample.sqlite --sql-file query.sql \
        --format html --param who=小明 --null-text 未填写 \
        --description 筛选小明 --output report.html

等价的函数调用（先 read_sql_file，再 export_html）：

    import report

    sql_text = report.read_sql_file("query.sql")
    count = report.export_html(
        "sample.sqlite", sql_text, "report.html",
        params={"who": "小明"},
        null_text="未填写",
        description="筛选小明",
    )
    # count == 1

三、who 改为不存在：返回 0，只剩表头，说明仍在
------------------------------------------------

只把参数值换掉，其余不变：

        --description 筛选小明 --output miss.html

函数入口等价于 params={"who": "不存在"} 调用 export_html。

四、说明区域的规则（省略/空串/空白/中文/转义）
------------------------------------------------

1. 有无区域的唯一判据是 description != ""（report.py:501）。
   非空时在 <h1>（499）与 <table>（507）之间追加恰好一行
   `<p style="white-space:pre-wrap">…</p>`（504-506）。
2. 省略说明与传入空字符串：没有说明区域，且两种输出逐字节一致。
   - 函数入口：省略时取默认值 description=""（形参默认在 525）；
     显式传 "" 同样在 501 判为不追加。两条路径渲染输入完全相同。
   - 命令行：未提供 --description 时 argparse 给出 None
     （report.py:621），main 以 `description=args.description or
     ""` 归一为 ""（664）；显式 `--description ""` 直接得到 ""。
   - 现有断言：两次调用产物二进制逐字节相等、省略时标题与表格
     之间的片段恰为 "\n"（test_report.py:2754-2774，字节比较
     2767-2770）。
3. 只有空白的非空说明（如 "  \n\t  "）仍产生独立区域：501 的
   判定不做 strip。现有断言 test_report.py:2739-2750。
4. 中文、首尾空格、连续空格与换行完整保留：说明文本经
   html.escape 转义但空白不删改（report.py:505），<p> 上的
   white-space:pre-wrap 令浏览器保留空白与换行；文件中新line
   字符本身原样存在。单元格也有同样的 pre-wrap 样式（494-495）。
   现有断言（两字首空格、连续两空格、换行均在转义文本中）
   test_report.py:2730-2733。
5. HTML 特殊字符按文字转义，不产生标签：说明经 html.escape
   （report.py:505，默认 quote=True），&、<、>、双引号、单引号
   分别写为 &amp;、&lt;、&gt;、&quot;、&#x27;；`<script>` 形态
   只显示为文字，页面中不存在该标签。现有断言：说明区含
   &lt;script&gt;、整页不含 "<script"、说明原始文本不出现
   （test_report.py:2734-2737）。表头（510）与数据单元格（516）
   适用同一转义：小红的备注若被选中，页面上呈现
   `中文,含&quot;引号&quot;`（逗号不是 HTML 特殊字符）；五种
   转义形态的通用断言见 2196-2203。
6. 说明不进入浏览器标题（<title> 固定为“查询报告”，
   report.py:491）、表头、数据行，也不进入 SQL：它只在渲染时
   作为参数传给 render_html（552），_execute_query 的调用
   （549-551）与函数签名（376）中都没有它。现有断言：标题不含
   说明、表格仍为原结果（test_report.py:2722-2725）；行数恒为
   数据行数（2720、2747、2765-2766）。


五、失败示例（仅覆盖以下三种）
------------------------------

三种失败共同约定：不创建新报告；若输出路径上已有文件，其字节
保持不变（各用例的具体保证见下）。

5.1 函数入口传入 description=None（ValueError）

    report.export_html(
        "sample.sqlite", sql_text, "bad.html",
        params={"who": "小明"}, description=None,
    )

export_html 的第一步类型检查即失败：None 不是 str，抛
ValueError("description 必须是字符串，收到 NoneType")
（report.py:545-548，类型名取 type(None).__name__）。该步在
_execute_query 调用（549）之前：不校验其余参数、不打开源库、
不渲染、不创建 bad.html。

现有断言：对 (None, 1, True, ["说明"]) 四值均
assertRaises(ValueError) 且目标路径不存在（test_report.py:
2793-2804）；断言只检查异常类型与无文件，错误信息逐字文本按
report.py:546-548 推导。

5.2 命令行把 --description 与 CSV 格式搭配（退出码 1）

    python report.py --db sample.sqlite --sql-file query.sql \
        --format csv --param who=小明 \
        --description 筛选小明 --output x.csv

按源码推导：parse_args 中 args.description 非 None 且
args.format != "html"，调用 parser.error（report.py:630-633）；
自定义 _Parser.error 先 print_usage(sys.stderr)（563）再经 die
输出一行“错误: 参数错误：--description 仅支持 --format html：
CSV 报告不包含查询说明文本”（564、59、631-632），sys.exit(1)
（60）。拒绝发生在 parse_args 内（639），早于读取查询文件
（644）与任何导出动作，故不读文件、不开库、不建 x.csv。

预期：退出码 1；标准错误含用法行及上述原因（含“错误: ”、
“--description”、“html”）；标准输出为空；不创建新报告，输出
路径上若已有文件则字节不变。

现有断言：显式 csv 用例 test_report.py:2894-2898，公共断言
2882-2892（退出码 1、stderr 包含性检查、stdout == ""、目标
不存在）；同目录预置文件字节不变的用例 2914-2926（断言退出码
1、stdout 为空与字节相等，未逐字断言 stderr）。标准错误的
完整逐字文本按 report.py:562-564、631-632 推导。

5.3 命令行使用已存在的输出目标（退出码 1）

先向 report.html 写入任意字节，再执行第二节的成功命令。

按源码推导：参数解析（顺序 1）与查询文件读取（顺序 2）正常；
export_html 的 description 类型检查通过（545-548），进入
